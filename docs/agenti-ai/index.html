Agenti AI nel Lab

DataCivicLab è progettato per essere interrogabile anche dagli agenti AI (Claude, OpenCode, Cursor, …) tramite MCP (Model Context Protocol). Questo vale per chi contribuisce e per chi legge: la stessa infrastruttura che usiamo internamente è pubblica.

Il server per partecipare: dataciviclab

Il server unico del Lab (dcl-mcp) espone 11 tool in tre famiglie:

FamigliaToolCosa permette
Contestosession_bootstrap, lab_map, find, explore, workspace_triageOrientamento, ricerca dataset/analisi, card con schema e path, stato del Lab
Discussionigithub_list_discussions(query=…), github_get_discussion(include_comments=True), github_create_discussion, categorieLeggere e partecipare alle Discussion su GitHub
Dati pubblicigcs_query(slug, sql, layer=)SELECT read-only (anche CTE) sui parquet clean/mart dei bucket pubblici

Con questo solo server un agente può: trovare un dataset rilevante (find → explore), verificarlo con una query SQL (gcs_query) e aprire o rispondere a una discussione (github_*) — senza clonare nulla.

Installazione

pip install "lab-connectors[mcp,duckdb] @ git+https://github.com/dataciviclab/lab-connectors.git"
pip install "dcl-mcp @ git+https://github.com/dataciviclab/dcl-mcp.git"

Configurazione (esempio generico MCP):

{
  "mcpServers": {
    "dataciviclab": {
      "command": "dcl-mcp"
    }
  }
}

Per le discussions serve un GITHUB_TOKEN (GraphQL autenticato anche in lettura). Il resto funziona senza token.

Regole (valgono anche per gli agenti)

Gli agenti operano con le stesse regole delle persone:

  • I numeri vanno verificati con una query prima di essere pubblicati — una card o una description non bastano.
  • Le PR usano il template del repo; mai mergiare senza review umana.
  • Le Discussion sono il luogo delle domande e delle proposte: leggi prima di scrivere, cerca se la domanda è già stata fatta.

Il workspace multi-repo e il setup completo sono in Setup locale. Per i dettagli tecnici del server: dcl-mcp.
